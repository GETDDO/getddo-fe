# ADR-0001: FSD 레이어 아키텍처 채택

- 상태: accepted
- 날짜: 2026-09-17

## 맥락

팀 프로젝트 + AI 에이전트 협업 환경에서는 "규칙을 아는가"가 아니라 "규칙이 기계적으로 강제되는가"가 품질을 결정한다. 자유로운 폴더 구조는 사람마다 import 방향이 달라지고, 에이전트는 세션마다 다른 위치에 코드를 생성한다.

## 결정

FSD(Feature-Sliced Design) 6레이어를 채택하고 `eslint-plugin-boundaries`로 의존 방향을 커밋·CI에서 강제한다.

- 의존 방향: `app → pages → widgets → features → entities → shared`
- 슬라이스는 `index.ts`(공개 API)를 통해서만 import한다
- 같은 레이어의 다른 슬라이스 참조는 금지. 공유가 필요하면 `shared`/`entities`로 내린다

## 결과

- 신규 코드의 위치가 규칙으로 결정되어 리뷰·에이전트 결과물의 편차가 줄어든다
- 규칙 위반은 사람이 잡는 게 아니라 `npm run lint`가 잡는다
- 비용: 슬라이스 간 공유 로직을 어디에 둘지 매번 판단해야 하고, 잘못 내린 코드는 리팩터링이 필요하다
