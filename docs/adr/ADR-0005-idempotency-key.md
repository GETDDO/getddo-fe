# ADR-0005: 중복 위험 요청에 멱등키 적용

- 상태: accepted
- 날짜: 2026-09-17

## 맥락

응모·추첨은 되돌리기 어려운 부작용을 만든다. 네트워크 재시도나 더블클릭으로 같은 요청이 두 번 가면 응모가 중복 생성되거나 응모권이 이중 차감될 수 있다. 클라이언트에서 버튼 비활성화만으로는 재시도를 막을 수 없다. 공용 명세도 "같은 요청의 재시도와 새로운 응모를 구분해 중복 반영을 방지한다"고 명시한다 (`../getddo-spec/02-domain/entry.md`) — 응모권 차감이 없는 미사용 이벤트 응모에도 적용된다.

## 결정

"재시도·중복 클릭으로 같은 부작용이 두 번 생기면 안 되는 POST"에는 `shared/lib/idempotency-key`의 `createIdempotencyKey()`로 생성한 키를 헤더에 붙인다.

- 현재 대상: `POST /events/:eventId/entries`(응모 — 사용·미사용 이벤트 모두)
- 헤더명·생성 주체·전달 방식은 FE-BE 미합의 — 임시로 `X-Idempotency-Key`를 쓰며, 합의 시 공통 상수로 승격한다
- 조회(GET)와 이미 멱등인 요청에는 붙이지 않는다

## 결과

- 새로운 부수효과 POST(추첨, 재추첨, 응모권 회수 등)를 추가할 때 멱등키 필요 여부를 먼저 판단한다
- MSW 핸들러가 멱등키 누락 시 400(`IDEMPOTENCY_KEY_REQUIRED`)을 반환하므로, 목업 환경에서 누락을 바로 발견할 수 있다
