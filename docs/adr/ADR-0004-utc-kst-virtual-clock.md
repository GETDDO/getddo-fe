# ADR-0004: UTC 수신 + KST 표시 + 가상 시계

- 상태: accepted
- 날짜: 2026-09-17

## 맥락

이벤트 시작·마감, 출석 당일 판정, 응모권 월 만료처럼 날짜 경계를 넘는 판정이 도메인 전반에 퍼져 있다. 브라우저 로컬 타임존에 맡기면 KST가 아닌 환경에서 판정이 어긋난다. 또한 관리자 시연에서 "마감 후 추첨" 같은 미래 시나리오를 실제 시간을 기다리지 않고 보여줄 방법이 필요하다.

## 결정

- 서버와는 UTC ISO 8601 문자열로만 주고받는다
- 화면 표시와 날짜 비교는 `shared/lib/date`의 KST 함수(`formatKst`, `isSameKstDate`)로만 처리한다
- 시간 판정 로직의 "지금"은 `useVirtualClock().now()`(`app/virtual-clock`)에서 가져온다 — 관리자가 `setOverride`로 시각을 오버라이드할 수 있다
- 일일 초기화 기준은 기획서대로 **00:00 UTC(=09:00 KST)**다 — 출석·게임 보상·응모권 월 만료가 이 기준을 공유한다. KST 자정 기준으로 "오늘"을 판정하지 않는다
- 마감 판정은 서버 책임이다 — 클라이언트 시각으로 마감을 판정해 요청을 막지 않는다

## 결과

- 타임존 판정이 한 파일(`shared/lib/date.ts`)에 모인다
- `new Date()` 직접 호출은 시간 판정 로직에서 금지 — 가상 시계를 우회하면 시연 기능이 깨진다
- `toKst` 반환값은 UTC 메서드로 KST를 읽는 비교 전용 값이다. 표시에 쓰면 9시간 어긋나 보인다
- "하루"의 경계가 KST 자정이 아니므로, `isSameKstDate`로 날짜만 같다고 초기화 경계가 같은 것은 아니다 — 초기화 판정은 UTC 날짜 기준이다
